# New Zealand new residential floor area and embodied carbon, 2026–2050

Code, data and outputs of the paper **[paper title]** (manuscript in preparation; the DOI is added at publication).

The model projects the new residential floor area New Zealand builds in 2026–2050 and its embodied carbon, compares it
with New Zealand's share of a global climate boundary, and tests ten levers that reduce it. Model version 5.0.0.

## The model in six steps

1. **Stock.** Population and household projections (Stats NZ) give households; with vacancy, replacement and the
   building pipeline (consents and completions) they give the dwellings built each year (`projection.py`).
2. **Floor area.** Dwellings × dwelling size by typology give the new floor area, split by reason for building
   (population growth, smaller households, extra space, vacancy, replacement).
3. **Carbon.** Floor area × case-study life-cycle factors of 16 New Zealand buildings gives embodied carbon by stage:
   A1–A5, soil carbon loss, maintenance (B2, B4) and the emissions committed after 2050 (`Building_factors.py`,
   `events.py`), with material production decarbonising along Horup et al. (2025).
4. **AESA budgets.** The sector's share of a global climate boundary under acquired rights (AR) and ability to pay
   (AtP) gives annual budgets and the cumulative level of exceedance, LoE (`boundaries.py`, `aesa.py`).
5. **Levers and pathways.** Ten levers (PAS 2080: Avoid L1–L5, Switch L6–L8, Improve L9–L10) at four levels give the
   Moderate and Ambitious Pathways and the Theoretical Limit, with exact Shapley attribution (`levers.py`,
   `pathways.py`).
6. **Uncertainty.** One-at-a-time sensitivities, replacement variants, a Monte Carlo of 5,000 draws with Sobol indices,
   and hindcasts against the census record (`MonteCarlo.py`, `pathways_mc.py`, `Sensitivity.py`, `validation.py`).

Module by module: [ARCHITECTURE.md](ARCHITECTURE.md). Rule for the Theoretical Limit: `levers.TL_RULE`; every lever and
level with its source: [outputs/reports/LEVERS_TABLE.md](outputs/reports/LEVERS_TABLE.md).

## Repository structure

```
run_all.py            the pipeline (every step in its own process)
*.py                  model modules (projection, carbon, AESA, levers, pathways, Monte Carlo)
figures/              every figure, drawn from outputs/data/ only
tools/                tables, reports, checks
data/                 raw inputs (data/raw/, MANIFEST.csv), builders (data/build_*.py), derived inputs (data/derived/)
outputs/              the full-profile results: data/, paper_main/, paper_extended/, supplementary/, reports/
tests/                tests and the regression lock
docs/                 data provenance, references, palette
```

Figures and tables use the manuscript numbers (Fig1–Fig7, ED1–ED9, EDT1, SF1–SF16, ST1–ST13); every item with its
caption and data files: [outputs/FIGURES.md](outputs/FIGURES.md); every output file and the script that writes it:
[outputs/INDEX.md](outputs/INDEX.md).

## How to reproduce

Python 3.11 with the pinned packages:

```bash
python3.11 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
```

```bash
python run_all.py --profile full
```

| profile | writes | Monte Carlo | Sobol | figures | run time |
|---|---|---|---|---|---|
| full (the reported results) | `outputs/` | 5,000 draws | yes | PNG 600 dpi | about 40 min |
| light (default; checks) | `outputs/_light/` (not versioned) | 1,000 draws | no | PNG 200 dpi | about 8 min |

The deterministic results do not depend on the profile. The run stops at the first failed step and names its log.
Tests run on the outputs of the active profile:

```bash
PATHWAY_PROFILE=full python -m pytest tests
```

`tests/regression_lock.json` holds the SHA-256 of every deterministic data file and of the Monte Carlo draws; see
[tests/README.md](tests/README.md).
